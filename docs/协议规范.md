# StarRing Ultra 2026 控制协议规范

> 适用设备：StarRing Ultra 2026（型号标识 `ringUltra_2026`）
> 控制通道：经典蓝牙 SPP / RFCOMM（非 BLE GATT）
>
> 本文描述该型号耳机的控制协议，包括传输通道、帧结构、命令码与各功能 payload 语义，以及 App 侧的状态同步模型。

---

## 1. 传输通道

| 项 | 值 |
| --- | --- |
| 通道类型 | 经典蓝牙 SPP / RFCOMM |
| SPP UUID | `00001101-0000-1000-8000-00805F9B34FB` |
| RFCOMM 通道号 | `28` |
| 产品识别码 | `525400040001` |
| 设备名称（经典侧） | 形如 `StarRing Ultra 2026` |
| 设备名称（BLE 侧） | 形如 `StarRing Ultra_BLE` |

建连要点：

1. 已配对设备即可直接建立 RFCOMM 连接，无需扫描；**建连前应取消正在进行的系统扫描**，否则可能阻塞连接。
2. 通过 SDP 记录解析出的通道号可能并非实际控制通道（现象为「命令能发出去但收不到应答」）。
   因此建连顺序为：按通道号 `28` 直连（先非安全、再安全）→ 回退 SDP UUID（先安全、再非安全）。
3. 控制通道位于**经典蓝牙侧**，因此应选择名称含目标线索且不含 `_ble` 的配对项。

## 2. 帧格式

```text
┌────┬────┬───────┬──────┬──────────┬───────────┬──────────┬──────┐
│ b0 │ b1 │ b2-b3 │  b4  │  b5-b6   │    b7     │   b8..   │ last │
└────┴────┴───────┴──────┴──────────┴───────────┴──────────┴──────┘
```

| 偏移 | 含义 |
| --- | --- |
| `b0` | 方向标识：请求 `0x08` / 应答 `0x09` |
| `b1` | 同步字：请求 `0xEE` / 应答 `0xFF` |
| `b2-b3` | 保留，`0x0000` |
| `b4` | 请求 `0x00` / 应答 `0x01` |
| `b5-b6` | 命令码，**大端** |
| `b7` | **整帧总长度**（含校验字节本身） |
| `b8..` | payload，长度 = `b7 - 9` |
| `last` | 校验字节 |

### 2.1 校验

```text
checksum = (b0 + b1 + … + last-1) mod 256
```

即**逐字节求和取低 8 位**，不是 XOR，也不是 CRC。

### 2.2 读写命令关系

读命令与写命令共用同一命令号空间，区别只在低字节最高位：

```text
写命令 0x0X8Y  ←→  读命令 0x0X0Y
例：写 0x0682（设噪声模式） ←→ 读 0x0602（查噪声模式）
```

### 2.3 payload 规则

- **读请求必须携带 1 字节 payload `0x00`**（整帧长度 `0x0A`）。
  空 payload 的读请求设备**不回包**。
- **写命令 payload 一律以 `[0x00, …]` 起头。** 设备以首字节作为前导校验：
  首字节 ≠ `0x00` 时整条写命令被**静默丢弃**，且不会有任何错误应答。
- 帧末的校验和由帧构造过程算出，**不属于 payload**，不要当作字段一并发送。

### 2.4 应答特征

- 写入后设备会回一帧**同功能的应答**，命令码可能是写码，也可能是对应的读码，
  因此解析时应对同一功能的读写命令码**同时匹配**。
- 应答 payload 可能携带新值，也可能仅为 `[0x00]`。
  因此写操作的最终结果应以**随后的一次回读**为准。

## 3. 命令码总表

| 功能 | 读命令 | 写命令 | 写 payload |

| 音效 EQ | `0x0201` | `0x0281` | `[00, eq]` |

| 噪声模式 | `0x0602` | `0x0682` | `[00, m1, m2, m3, m4]` |
| 游戏模式 | `0x0603` | `0x0683` | `[00, onOff]` |
| 通透梯度 | `0x0604` | `0x0684` | `[00, level]` |
| 降噪触控清单 | `0x0605` | `0x0685` | `[00, 正常, 通透, 风噪, 降噪]` |
| 降噪梯度 | `0x0607` | `0x0687` | `[00, level]` |

## 4. 功能语义

### 4.1 噪声模式（`0x0602` / `0x0682`）

payload = `[00, m1, m2, m3, m4]`，其中 `m1` = 降噪 / 自适应降噪，`m2` = 正常，
`m3` = 风噪，`m4` = 通透，采用 one-hot 编码：

| 模式 | payload |
| --- | --- |
| 降噪 | `00 01 00 00 00` |
| 自适应降噪 | `00 02 00 00 00` |
| 正常 | `00 00 01 00 00` |
| 抗风噪 | `00 00 00 01 00` |
| 通透 | `00 00 00 00 01` |

说明：

- **「自适应降噪」不是独立命令**，而是噪声命令的一个取值（`m1 = 0x02`）。
- 降噪的深浅程度不由本命令控制，见 4.2 的降噪梯度。

### 4.2 梯度档位（`0x0687` 降噪 / `0x0684` 通透）

payload = `[00, level]`，三档。**两个梯度的档位方向相反**：

| 档位 | 降噪梯度 `level` | 通透梯度 `level` |
| --- | --- | --- |
| 深度 | `0x02` | `0x00` |
| 中度 | `0x01` | `0x01` |
| 轻度 | `0x00` | `0x02` |

### 4.3 触控映射（`0x0401` 读 / `0x0481` 写）

**写**（一次设置一格）：payload = `[00, ear, gesture, effect]`，共 4 字节。

| 字段 | 取值 |
| --- | --- |
| `ear` | 左耳机 `0x00` / 右耳机 `0x01` |
| `gesture` | 单击 `0x00` / 双击 `0x01` / 三击 `0x02` / 长按 `0x05` |
| `effect` | 增大音量 `0x00` / 减小音量 `0x01` / 上一曲 `0x02` / 下一曲 `0x03` / 语音助手 `0x04` / 播放暂停 `0x05` / 无作用 `0x06` / 降噪控制 `0x07` |

**读**（整表）：payload = `[00, 左耳机 4 个手势, 右耳机 4 个手势]`，共 9 字节，
按 **单击、双击、三击、长按** 排列，值为上述效果码。

写帧示例（左耳机 + 双击 + 上一曲）：

```text
08 EE 00 00 00 04 81 0D 00 00 01 02 8B
                                   └─ 校验和：0x88 + ear + gesture + effect = 0x8B
```

### 4.4 降噪触控清单（`0x0605` 读 / `0x0685` 写）

payload = `[00, 正常, 通透, 风噪, 降噪]`，开启置 `0x01`，未开启置 `0x00`。
**读写格式完全对称。**

该清单决定触控效果中「降噪控制」可轮换的噪声模式；**至少需开启 2 个模式**。
每次长按在清单内切换到下一种模式，不会切到未开启的模式。

写帧示例（开启风噪 + 降噪）：

```text
08 EE 00 00 00 06 85 0E 00 00 00 01 01 24
```

### 4.5 开关类命令与极性

payload 均为 `[00, onOff]`，但**各命令的开关极性并不统一**：

| 功能 | 命令码 | 开 | 关 |
| --- | --- | --- | --- |
| 游戏模式 | `0x0603` / `0x0683` | `0x00` | `0x01` |
| 双设备连接 | `0x0802` / `0x0882` | `0x01` | `0x00` |
| 触控开关 | `0x0A01` / `0x0A81` | `0x00` | `0x01` |
| 入耳检测 | `0x0C01` / `0x0C81` | `0x00` | `0x01` |

### 4.6 编码协议（`0x0801` / `0x0881`）

payload = `[00, codec]`：

| 值 | 编码 |
| --- | --- |
| `0x00` | AAC / SBC |
| `0x01` | LDAC |
| `0x02` | LHDC |
| `0x03` | LDAC + LHDC |

**切换编码协议会使耳机重启**，连接会短暂中断，之后需重新建立连接。

### 4.7 音效 EQ（`0x0201` / `0x0281`）

payload = `[00, eq]`：`0x00` = HIFI，`0x01` = POP，`0x02` = ROCK。

### 4.8 提示音等级（`0x0E03` / `0x0E83`）

payload = `[00, level]`，取值 `0x00`–`0x04`，对应一档至五档，提示音音量递增。

### 4.9 查找设备（`0x0E82`）

payload = `[00, action, flag]`：

| 动作 | payload |
| --- | --- |
| 左耳机响铃 | `00 00 01` |
| 右耳机响铃 | `00 01 01` |
| 停止响铃 | `00 03 00` |

### 4.10 电量帧（`0x0101`）

payload 共 9 字节：

```text
[00, 左耳状态, 01, 左耳电量%, 右耳电量%, 充电标志, 仓在位, 仓电量%, 00]
  0     1       2       3           4          5        6        7     8
```

| 索引 | 含义 |
| --- | --- |
| 0 | 保留 |
| 1 | 左耳机状态（`0x01` = 出仓 / 佩戴，`0x00` = 在仓） |
| 2 | 恒为 `0x01` |
| 3 | **左耳机电量 %** |
| 4 | **右耳机电量 %** |
| 5 | 充电标志（入仓充电后由 `0x00` 变为 `0x01`） |
| 6 | 充电仓在位（`0x01` = 在位） |
| 7 | **充电仓电量 %**；`0xFF` = 不在仓 / 未知 |
| 8 | 保留 |

该帧与界面上的左耳机 / 右耳机 / 充电仓三格电量一一对应；
设备在空闲期也可能**主动上报**本帧。

## 5. 状态同步模型

设备的主动上报很少（空闲期仅偶发一次电量帧），因此状态同步由 App 侧主动发起：

1. **连接成功后立即全量回读**：按固定顺序下发 13 条读命令（电量、噪声、EQ、游戏、
   双设备、入耳、编码、降噪梯度、通透梯度、触控开关、提示音、触控映射、降噪触控清单），
   每条间隔 120 ms。
2. **回到前台时补一次全量回读**（`onResume`）。
3. **连接期间周期轮询**关键状态（电量、噪声、游戏、双设备、入耳、触控开关），周期 4 秒。
4. **支持手动重新加载**：用户可随时触发一次全量回读，界面以动画指示回读进度。

### 5.1 防回环

耳机端始终是权威状态源，App 本地仅缓存最近一次回读结果。为避免把本地缓存反向推回耳机：

- 所有控件回调都做**值比较**：只有用户操作导致的值变化才下发命令；
- 程序化回填（初始化、状态回读）期间用统一的抑制开关（`suppressCallbacks`）屏蔽回调——
  单选组在程序化设置选中项时也会派发回调，必须显式抑制；
- 下拉框的选中回调可能延迟到布局期派发，故值比较作为兜底保留；
- 分段滑动的控件为「拖动中只刷新档位文本、松手才提交」，避免一次拖动连发多条写命令；
- 多选组的多个勾选框**整体赋值**，避免出现「仅 1 个被选中」的中间态被校验规则回滚。

### 5.2 本地持久化

最近一次回读结果（电量、各设置项、触控映射表、降噪触控清单、上次连接设备）会写入
`SharedPreferences` 缓存，用于冷启动时先渲染界面；连接成功后由回读结果校正。
